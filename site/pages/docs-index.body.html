Language rules

The nine design rules

Braces, not invisible whitespace. One obvious way to do things. No silent type mixing. Conditions must be bool. No accidental globals. A missing key is an error. A captured variable is shared, not copied. Fast by default. A file’s names belong to that file.

What is in, and what is not

An honest list, in both directions. No remote packages yet, no compiled output, no inheritance.

The pipeline

Lexer, parser, module loader, type checker, compiler, bytecode, virtual machine — and a second, independent back end that has to agree with the first.

The shape of the language

If you have read nothing else, read this. It is the whole of Jin in about forty lines, and every line of it runs. 

# comments start with a hash

let x = 5                      # let declares
let name = "Jin"
x = x + 1                      # assign to an existing name

fn add(a, b) { return a + b }  # implicit return also works
fn sq(x) { x * x }

if x > 5 { print("big") } else if x == 5 { print("five") } else { print("small") }

for n in [1, 2, 3] { print(n) }        # also: for ch in "abc", for i in range(10)
while x > 0 { x = x - 1; if x == 2 { break } }

let f = fn(v) { v * 2 }                # anonymous functions
print("{name} has {len(name)} letters")
print("use {{braces}} for literal braces")

let person = {"name": "Ada", "age": 36} # a map
print(person["name"], has(person, "job"))
for field in person { print(field) }    # maps loop over their keys

That is the shape of it. Braces instead of whitespace, {interpolation} inside strings, optional type annotations, and a standard library small enough to keep in your head.
