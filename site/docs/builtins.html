What built-ins are

Jin ships with 54 built-in functions. They are written in Go, live in one file (builtins.go), and are shared by both back ends: the bytecode VM that jin run uses, and the tree-walking interpreter that jin interpret uses. There is only one implementation of each one, so the two engines cannot drift apart.

You call them like any other function:

print(len("hello"))
print(join(["a", "b"], ", "))
5
a, b

Built-ins never raise a name of their own — there is no math.len and no str.len — so a program only ever has one len in it. Multi-word names use an underscore, so starts_with is the shape to expect from anything added later.

Note. Every built-in is checked before your program runs. A wrong argument count or a wrong argument type is a type error, reported by jin check with the line and column, not a surprise in the middle of a loop.

I/O

NameSignatureReturnsWhat it does
printprint(a, b, ...)nilPrints every argument, separated by a space, then a newline.
inputinput()
input(prompt)		strReads one line from standard input, without its line ending. With a prompt, the prompt is written out first.
read_all_stdinread_all_stdin()strReads everything left on standard input and returns it as one string.

input and read_all_stdin share one buffered stream, so a program can mix them: read a name with input, then the rest with read_all_stdin.

let name = input("Your name? ")
print("Hello, {name}!")
Your name? Hello, Ada!

Careful. print separates its arguments with a space and adds a newline. It does not add a space between a value and the end of the line, so print("a", "b") writes a b and nothing else. print with no arguments writes a blank line.

Note. len, find, chars, slice and reverse count characters, not bytes. len("héllo") is 5 and find("héllo", "llo") is 2.

Note. lines normalises Windows line endings to \n and drops one trailing newline. An empty string gives an empty array, and blank lines in the middle are kept.

Careful. push does not change the array you gave it. It builds a new one and hands that back, so the result has to be assigned: items = push(items, x). Forgetting the assignment is the most common Jin mistake.

Note. sort needs one kind of value. An array of numbers sorts as numbers and an array of strings sorts as strings, but a mixture of the two is refused rather than guessed at.

Maps

NameSignatureReturnsWhat it does
hashas(map, key)boolTrue when the map has that key.
getget(map, key, default)anyThe value under the key, or default when the key is not there.
deletedelete(map, key)nilRemoves the key from the map. The map is changed in place.

valuesvalues(map)arrayThe map's values, in the order they were added.

A map's keys may be an int, a str or a bool. Entries keep the order they were added in, so printing a map and looping over one are both predictable.

let counts = {}
for w in ["pear", "apple", "pear", "fig"] {
    counts[w] = get(counts, w, 0) + 1
}
print(counts)
print(len(counts))
print(keys(counts))
print(values(counts))
print(has(counts, "pear"), has(counts, "plum"))
print(get(counts, "plum", 0))
delete(counts, "fig")
print(counts)
print(contains(counts, "pear"))
{"pear": 2, "apple": 1, "fig": 1}
3
["pear", "apple", "fig"]
[2, 1, 1]
true false
0
{"pear": 2, "apple": 1}
true

Careful. get always takes three arguments. The default is not optional, because a missing key is an error in Jin, not a quiet nil: get(map, key) is a type error, and map[key] on a key that is not there stops the program.

Note. contains on a map looks at the keys, not the values. contains(counts, "pear") is true because "pear" is a key, not because 2 is a value.

Note. len on a map counts entries, not keys and values separately. delete changes the map in place, so there is nothing to assign — but it returns nil, and deleting a key that is not there is not an error.

Functional

The function you pass can be a named function, an anonymous function, a closure, or a built-in such as str. It is called with one element, except for reduce, which gets two, and sort_by, which gets two to compare.

fn double(n: int) -> int {
    return n * 2
}

print(map([1, 2, 3], double))
print(map([1, 2, 3], str))
[2, 4, 6]
["1", "2", "3"]

A bound method works too, as long as it takes one argument of its own — the one element the built-in hands it.

let nums = [4, 9, 2, 7]
print(map(nums, fn(x) { return x * x }))
print(filter(nums, fn(x) { return x % 2 == 0 }))
print(reduce(nums, fn(total, x) { return total + x }, 0))
print(any(nums, fn(x) { return x > 8 }))
print(all(nums, fn(x) { return x > 0 }))
print(find_index(nums, fn(x) { return x > 5 }))
print(sort_by(nums, fn(a, b) { return b - a }))
[16, 81, 4, 49]
[4, 2]
22
true
true
1
[9, 7, 4, 2]

Careful. reduce takes the function second and the starting value third: reduce(array, fn, seed). The function is called as fn(acc, element), so the accumulator comes first.

Note. sort_by is stable: elements the comparator calls equal keep the order they were in. sort_by also leaves the array you passed it alone.

Note. filter, any, all and find_index insist on a bool from the predicate. There is no implicit truthiness: a predicate that returns a number is an error, not a truthy value.

write_file("notes.txt", "first\nsecond\n")
append_file("notes.txt", "third\n")
print(file_exists("notes.txt"))

Note. A failed file operation is a catchable error. Wrap it in try / catch, or check with file_exists first.

Note. Paths are relative to the folder the program was started in, not to the folder the file lives in.

Program

NameSignatureReturnsWhat it does
argsargs()array of strThe arguments the program was run with, in order.

Whatever follows the file name on the command line reaches the program here, which is what makes a Jin file usable as a command.

let who = args()
if len(who) == 0 {
    print("no arguments given")
} else {
    print("hello, {who[0]}")
}
$ jin run greet.jin
no arguments given
$ jin run greet.jin Ada
hello, Ada

See Command Line for how the arguments are separated from Jin's own options.

Control

NameSignatureReturnsWhat it does
errorerror(message)nothingStops the program with an error. The message is the text you give it.

error inside a catch block re-raises the error to the enclosing handler, keeping the position the error came from.

try {
    let val = 1 / 0
} catch err {
    print("logging error: {err}")
    error(err)
}
$ jin program.jin
logging error: 2:17: division by zero
jin: 2:17: division by zero
$ echo $?
1

The message keeps the position the error came from, not the position of the error call, and the program still ends with exit code 1.

See Error Handling for the whole story.

Gotchas

These are the things that bite. All of them are checked before the program runs, so you find them with jin check rather than halfway through a loop.

  • get needs a default. get(map, key) is a type error: get(map, key, default) is the only shape there is.
  • push, sort, reverse and slice return a new value and leave the original alone. items = push(items, x) — the assignment is not optional.
  • delete and m[key] = value change the map in place. There is nothing to assign for those.
  • contains on a map checks the keys, not the values.
  • join needs a separator. join(array) is a type error; use join(array, "") when you want no separator at all.
  • reduce takes the function second and the seed third: reduce(array, fn, seed).
  • sort_by is stable, so equal elements keep their original order.
  • len of a map counts entries.
  • sort refuses an array that mixes numbers and strings.
  • find counts characters, not bytes, and gives -1 when the text is not there.
  • floor, ceil and round always give an int, even when the argument was a float.
  • random() with no arguments gives a float; with one or two it gives an int.
  • repeat refuses a negative count.
  • There is no implicit truthiness anywhere: a condition has to be a bool, and a predicate has to return one.

Careful. A local or a global that reuses a built-in's name hides it — in the type checker as well as at run time. See Shadowing a built-in below.

Shadowing a built-in

Every name in Jin lives in one scope, and a name you declare wins over a built-in of the same name. The type checker sees it too, so the built-in's own signature check is skipped for that name rather than complaining.

let len = "the global one"
print(len)

fn show() {
    print(len)
}

show()

fn local_len() {
    let len = "the local one"
    print(len)
}

local_len()
print(len)
the global one
the global one
the local one
the global one

The global len hides the built-in for the whole file. Inside local_len the local len hides the global one, and only for that function.

Note. The same rule stops an import alias from being a built-in name: import "utils" as print is refused before the program runs.

Worked example

Here is a short program that puts several groups together: it reads a file, cleans the text up, counts the words, orders them, and writes a report.

let lines_in = lines(read_file("data.txt"))
let words = []
for line in lines_in {
    for w in split(trim(line), " ") {
        if w != "" {
            words = push(words, lower(w))
        }
    }
}
print(words)

let counts = {}
for w in words {
    counts[w] = get(counts, w, 0) + 1
}

let top = sort_by(keys(counts), fn(a, b) {
    return get(counts, b, 0) - get(counts, a, 0)
})
print(top)

let report = []
for w in top {
    report = push(report, "{w}: {get(counts, w, 0)}")
}
write_file("report.txt", join(report, "\n") + "\n")
print(read_file("report.txt"))
delete_file("report.txt")

With data.txt holding three lines of text:

["the", "quick", "brown", "fox", "jumps", "over", "the", "lazy", "dog", "the", "end"]
["the", "quick", "brown", "fox", "jumps", "over", "lazy", "dog", "end"]
the: 3
quick: 1
brown: 1
fox: 1
jumps: 1
over: 1
lazy: 1
dog: 1
end: 1

Note. The order of the words that come out is the order they were added to counts, not the order of the counts. sort_by only decides the order of the top list, and equal counts keep the order they arrived in.
