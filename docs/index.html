Version 0.10.1 · MIT or Apache-2.0 licensed · Written in Go, no dependencies

Write it the easy way.
Run it the fast way.

Jin is a small, statically checked, bytecode-compiled language. It reads like Python, it refuses to let the quiet mistakes through, and it runs on a real virtual machine instead of a tree of interpreter nodes.

  • Errors are caught before the program starts
  • No third-party dependencies — not one
  • Closures, records, try/catch, projects and imports
  • Two independent engines, forced to agree byte for byte
Get started Take the tour

Go 1.21 or newer is the only thing you need. Then go build -o jin.exe . and you have a language. Installation and the first program →

Jin 0.10.1 stage 10 — input, records, built-ins

Ten stages, one language

Lexer, parser, type checker, compiler, virtual machine, standard library, projects and imports.

Nothing sneaks past

Undeclared names, mixed types, wrong argument counts and non-bool conditions are all compile-time errors.

Bytecode, not a tree walk

Names resolve to slots before the program starts. Small integers, booleans and nil are pooled.

Fast by default

Around six times quicker than Jin’s own tree-walking reference engine, and level with CPython.

Run Jin in your browser

Type a program, press Run, and watch it work. This is a real interpreter for a subset of Jin, running in your browser — no server, no install, no telemetry.

      Why Jin
      
The easy way to write it is the correct way

      

        Python is pleasant to write and unpleasant to debug, because most of
        its worst surprises are quiet ones. Jin keeps the readability and
        turns the surprises into errors.
      

    


    

      

        
          
        
        
Mistakes are errors, not surprises

        

          A missing dictionary key, a truthy integer in an if, a
          typo that quietly creates a global — each one is a message
          with a line and a column, delivered before the program runs.
        

        See the type system
      


      

        
          
        
        
Braces, not invisible whitespace

        

          No broken programs because of a stray tab. A block is a block, and
          the shape of the code is the shape of the program.
        

        Take the tour
      


      

        
          
        
        
One obvious way to do things

        

          No decorators, no metaclasses, no dunder magic, no implicit
          truthiness. A small standard library you can hold in your head.
        

        Browse the built-ins
      


      

        
          
        
        
Projects, with namespaced files

        

          A folder with a jin.toml is a project. Import another
          file under an alias and its names live behind that alias, so two
          files can never collide by accident.
        

        Projects and imports
      

    

  






  

    

      A look
      
A language you can read in a minute

      

        Braces instead of whitespace, {interpolation} inside
        strings, optional type annotations, and a standard library small
        enough to keep in your head.
      

    


    

      

        
Closures that share

        

          A captured variable is the variable, not a snapshot. Two functions
          written side by side see each other’s writes to it, and every
          pass of a loop gets its own binding.
        

        
fn counter() {
    let n = 0
    return fn() {
        n = n + 1
        return n
    }
}

let next = counter()
print(next(), next(), next())   # 1 2 3

      


      

        
Records with methods

        

          User-defined types with named fields, constructed positionally or by
          name, with methods declared in receiver syntax and bound methods
          that are ordinary first-class values.
        

        
struct Point { x: int, y: int }

fn (p: Point) shift(dx: int, dy: int) -> Point {
    p.x = p.x + dx
    p.y = p.y + dy
    return p
}

let p = Point{x: 20, y: 10}
p.shift(5, -10)
print(p)          # Point{x: 15, y: 10}

      


      

        
Errors you can catch

        

          Everything that stops a running program can be caught: failed file
          operations, out-of-bounds indices, missing map keys, division by
          zero, and your own error() calls.
        

        
try {
    let text = read_file("notes.txt")
    print(text)
} catch e {
    print("failed: {e}")
}
