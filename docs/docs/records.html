Declaring a record

A record is a type you write yourself: a name, and a fixed list of typed fields. It is declared with struct, at the top level of a file:

struct Point {
    x: int,
    y: int
}

The name after struct becomes a type. It can be used to make records, and it is the name that shows up in error messages and in type().

Note. A struct belongs to the file it is written in. It cannot be declared inside a function or a block — the compiler says 'struct' is only allowed at the top level of a file if you try. The same is true of methods.

One running example

The rest of this page walks through a single file. Save it as rec_demo.jin:

struct Point {
    x: int,
    y: int
}

struct Circle {
    center: Point,
    radius: int
}

# A method on Point, with 'p' as the receiver.
fn (p: Point) shift(dx: int, dy: int) -> Point {
    p.x = p.x + dx
    p.y = p.y + dy
    return p
}

# Named construction: any order, every field required.
let p = Point{y: 20, x: 10}
# Positional construction: fields in declaration order.
let q = Point(1, 2)

print(p, q)
print(p.x, p.y)

p.x = 15
print(p)

p.shift(5, -10)
print(p)

# A bound method is a value of its own.
let move = p.shift
move(1, 1)
print(p)

print(type(p), type(q))

# Nested records.
let c = Circle{center: Point(0, 0), radius: 25}
print(c)
print(c.center.x, c.radius)

Running it prints:

Point{x: 10, y: 20} Point{x: 1, y: 2}
10 20
Point{x: 15, y: 20}
Point{x: 20, y: 10}
Point{x: 21, y: 11}
Point Point
Circle{center: Point{x: 0, y: 0}, radius: 25}
0 25

Each section below explains one line of that output.

Making one

There are two ways to construct a record, and they make exactly the same thing.

Positionally, with the fields in the order they were declared:

let q = Point(1, 2)

By name, with the fields in any order:

let p = Point{y: 20, x: 10}

The named form uses braces, not parentheses — Point(y: 20, x: 10) is a syntax error, because that is a call. Every field must be given a value: there are no defaults, and no field may be left out.

Printing a record shows the type name and its fields, in the order they were declared:

Point{x: 10, y: 20} Point{x: 1, y: 2}

Reading and changing fields

A field is read with a dot, and written the same way:

print(p.x, p.y)

p.x = 15
print(p)
10 20
Point{x: 15, y: 20}

Records are reference values, the same way maps and arrays are. Assigning to a field changes the record itself, and everybody holding it sees the change — including a function that was given the record as an argument:

struct Point {
    x: int,
    y: int
}

fn move_it(p: Point, dx: int) {
    p.x = p.x + dx
}

let p = Point(1, 2)
move_it(p, 10)
print(p)
Point{x: 11, y: 2}

Careful. Because a record is a reference, let q = p does not make a copy. q and p are two names for the same record, and writing to a field of one writes to the field of the other.

Methods

A method is a function that belongs to a record type. It is declared at the top level of a file with receiver syntax: the receiver comes first, in brackets, and it names both the type and the variable the method works on.

fn (p: Point) shift(dx: int, dy: int) -> Point {
    p.x = p.x + dx
    p.y = p.y + dy
    return p
}

You call it with a dot, and the record is passed in for you:

p.shift(5, -10)
print(p)
Point{x: 20, y: 10}

The receiver is an ordinary variable. It can be named anything, and it is the same record the method was called on — so a method can change the record's fields, and those changes are seen by the caller.

Note. The return type is optional. A method that ends with a return of a value is written -> Point; one that only changes fields can leave it off and return nothing.

Bound methods are values

Reading a method off a record gives you the record and the method together, as one callable value. So a method can be stored in a variable and called later, and it still works on the record it came from:

let move = p.shift
move(1, 1)
print(p)
Point{x: 21, y: 11}

That is what makes methods work with the higher-order built-ins: map, filter, sort_by and the rest all take a function, and a bound method is one.

struct Point {
    x: int,
    y: int
}

fn (p: Point) doubled() -> int {
    return p.x * 2
}

let points = [Point(1, 0), Point(2, 0), Point(3, 0)]
print(map(points, fn(p) { p.doubled() }))
[2, 4, 6]

Nested records

A field can be another record, and a record can hold any number of them. The inner one is reached with another dot:

struct Circle {
    center: Point,
    radius: int
}

let c = Circle{center: Point(0, 0), radius: 25}
print(c)
print(c.center.x, c.radius)
Circle{center: Point{x: 0, y: 0}, radius: 25}
0 25

A method can walk through nested records the same way:

fn (c: Circle) area() -> int {
    return 3 * c.radius * c.radius
}

print(c.area())
1875

A record that refers to its own type

A field may be given the type of the record it is inside. That is what lets you build a linked list:

struct Node {
    value: int,
    next: Node
}

let head = Node(1, Node(2, Node(3, nil)))
let curr = head
let total = 0
while curr != nil {
    total = total + curr.value
    curr = curr.next
}
print("sum:", total)
sum: 6

The last node points at nil, which is how the loop knows to stop. A record type never has to be complete at the point it is declared.

What type() says

For a record, type() gives the name the type was declared under — not a generic word like "struct":

print(type(p), type(q))
Point Point

The same name is used in error messages, so a message about a Point reads the same whether it is about the type or about one of its instances.

Struct literals in conditions

Jin statements put the condition in front of a braced block — if cond { ... }, while cond { ... } — with no parentheses of their own. So a struct literal written straight into a condition would be read as the start of the block.

Put it in parentheses and it is unambiguous:

let p = Point{x: 1, y: 2}
if (p == Point{x: 1, y: 2}) {
    print("matched")
}
while (p != Point{x: 0, y: 0}) {
    print("not the origin")
    break
}
matched
not the origin

Leave the parentheses out and the parser says so. The first message is the one that explains it; the rest follow from it:

$ jin cond_noparen.jin
jin: cond_noparen.jin has syntax errors: 7:15: struct literals in conditions must be enclosed in parentheses, e.g. (Point{...}); 7:16: unexpected token ":"; 7:19: unexpected token ","; 7:21: struct literals in conditions must be enclosed in parentheses, e.g. (Point{...}); 7:22: unexpected token ":"; 8:20: expected :, got }; 9:1: unexpected token "}"

Struct literals inside an array, or inside any parenthesised expression, are fine without extra parentheses:

for p in [Point{x: 1, y: 2}, Point{x: 3, y: 4}] {
    print(p)
}
Point{x: 1, y: 2}
Point{x: 3, y: 4}

The mistakes you can make

Most of them are caught before the program starts, because the type checker knows what each field is.

A field left out

struct Point {
    x: int,
    y: int
}

let p = Point{x: 1}
$ jin check rec_missing.jin
jin: rec_missing.jin has type errors:
  6:14: missing field "y" in Point

A field of the wrong type

struct Point {
    x: int,
    y: int
}

let p = Point{x: "one", y: 2}
$ jin check rec_wrongtype.jin
jin: rec_wrongtype.jin has type errors:
  6:15: field "x": cannot use str where int is expected

A field the record does not have

$ jin check rec_unknown.jin
jin: rec_unknown.jin has type errors:
  6:27: Point has no field "z"

The wrong number of values

$ jin check rec_arity.jin
jin: rec_arity.jin has type errors:
  6:14: Point(...) expects 2 value(s), got 1

Reading a field that is not there, at run time

When the type checker cannot know what a value is — because it came back from a function with no annotation, say — the run time has the last word, and the mistake becomes a catchable runtime error instead:

struct Point {
    x: int,
    y: int
}

fn make() -> any {
    return Point(1, 2)
}

let r = make()
try {
    print(r.z)
} catch e {
    print("caught read:", e)
}
try {
    r.z = 5
} catch e {
    print("caught write:", e)
}
caught read: 12:12: Point has no field "z"
caught write: 17:6: Point has no field "z"

Note. Writing to a method is refused too, and says why: cannot assign to method "shift" of Point. A method is not a field, and there is nowhere to put a new one.
